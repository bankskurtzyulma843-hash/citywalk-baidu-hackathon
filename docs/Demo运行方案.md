# Demo 运行方案与真实验收

更新：2026-09-27，对应 PRD v0.5，Travelwise 设计落地版。

## 现在怎么跑

运行 `npm start`，打开 [本地 Demo](http://127.0.0.1:4173)。本机已配置 Agent Plan Token，默认进入真实百度数据模式，无需安装 npm 依赖。

需要后台运行时执行 `npm run demo:start`。它脱离启动终端运行，重复执行会检查并复用已有服务；日志为 `.data/demo-server.log`。电脑重启后需要再执行一次，不依赖对话中的临时运行会话。

本轮已验证“胡同里的咖啡时光”只读分享。运行后在路线页点击“分享行程”生成自己的链接；仓库不包含开发机的分享快照。链接只在运行服务的本机可访问，跨设备需要可达地址或公开部署。当前没有公网部署。历史分享的展示资源已出现缓存失效，不能以快照有效期推断地图资源有效期。

百度账号授权、Agent Plan 网页领取、CLI 读取现有 Token 已完成，没有要求传统开发者注册或创建 AK。Token 保存在本地私有 `.env`，不回显或提交 Git。不要再复制 `.env.example` 覆盖本机现有配置。

## 实际接入链路

| 部分 | 作用 |
| --- | --- |
| 官方百度 CLI v1.0.1 | 账号授权、查询并复用 Token；`npm run baidu:connect` 保存本地配置 |
| Agent Plan Place API | 完整地点需求检索，返回真实 UID、地址和 GCJ02 坐标 |
| Agent Plan Direction API | 逐段步行规划，读取真实米数、秒数及 `steps.path` 道路坐标 |
| 百度官方托管地图 | 真实 `resource_key` 在地图主区域展示道路，保留百度署名及外部入口 |
| 本地薄后端 | 服务端 Bearer 鉴权、数据校验、路线临时结果及只读分享快照 |
| 一句话规划接口 | 原文检索、明确地标补查、同片区选点和排序、逐段真实算路、建议停留 |
| 地图文档转发与资源检查 | 固定官方页面完整转发、资源缓存有效性检查，不读取凭证或提取 SDK 密钥 |

当前没有浏览器 AK，使用百度托管地图。检索图显示最近返回的候选点，编号是百度候选顺序；路线图默认一次显示所有真实路段，也可切换第 1→2、2→3 站。托管图与清单独立展示，不声称支持清单点击定位或自定义覆盖物联动。

若要使用自有 JSAPI 底图及可控覆盖物，再配置浏览器 AK。传统 Place/DirectionLite 服务端 AK 适配器保留；SK 不能作为浏览器 AK。

## 当前界面

采用用户选定的 Travelwise 设计方向：桌面左侧以城市探索照片卡片呈现可直接开始的散步主题，右侧以真实百度地图为主区域。主题筛选和一句话规划用于快速开始，行程清单用于查看或调整已经生成的路线。

首屏会初始化真实地图展示资源，不需要先逐站搜索；这次地图初始化不会加入地点、修改草稿清单或生成一条虚构行程。主题卡片点击后才发起该主题的规划请求。

6 张本地照片位于 `public/photos/`，用于胡同、咖啡、湖岸、上海街区和建筑等主题。它们是主题配图，不是百度接口返回的商户实景，也不作为地点当前状态的证明。作者、原作品与授权保存在 `public/photos/credits.json`；页面提供[图片来源与授权](http://127.0.0.1:4173/photos/credits.html)入口。

## 演示步骤

1. 打开首屏，查看左侧城市探索照片与右侧真实地图；可切换主题筛选。
2. 点击“胡同里的咖啡时光”，或输入“北京雍和宫附近，2小时，胡同和咖啡，3站”。
3. 一次生成 2–5 站中的所需站数、逐段道路与时间摘要，无需逐站搜、加、再算路。生成失败时原计划保留。
4. 查看默认的全程道路地图，底栏可按需切换分段与检索图；行程清单显示顺序和分段距离。
5. 按需修改停留或用“加一站”补充；顺序及地点变化需重新算路。地点选取规则和未核实偏好在折叠详情。
6. 直接生成只读链接；之后修改原行程不改变快照。首版无建房和登录。

## v0.4 界面与地图修复验收（历史记录）

2026-09-27 在用户当前的 Codex 内置浏览器复现了“搜索有结果、地图空白”。直接托管页导航未正常载入；转发完整官方页面并使用另一个 loopback 主机名作为 iframe 来源后，实际显示北京道路、步行路径、起终点和百度署名。iframe 与父应用保持不同来源；官方脚本、SDK 与资源协议不改写。该方式为本机 Demo 适配，公开部署须配置独立展示源或正式浏览器 AK。

当时真实的一句话规划返回：雍和宫 → S·O·E COFFEE（五道营店）→ 蛋咖啡 EGG COFFEE。两段为 424 米与 304 米，共 728 米；步行显示 13 分钟，每站建议停留 20 分钟，总计 73 分钟，预算为 120 分钟。一次点击完成选点和算路，并已直接生成分享快照。实际选择是地标优先和地点距离规则，偏好、营业与可进入状态尚未逐项核实。

成功搜索会切到此次搜索地图，并保留已生成道路供切回。资源接口返回空缓存时显示“地图资源已过期”和“更新地图”；分享页更新地图不会改写原分享地点与时间。文档加载事件不当作瓦片成功证据。

当时的 v0.4 界面在 390×844 手机视口中页面与视口宽度均为 390；地图区域高度约 454，路线起终点和道路可见；分享页隐藏需求输入、搜索、编辑与预算输入。该记录不作为本轮 Travelwise 手机端瓦片展示的验收结论。临时视口已恢复。

当时 42 项自动测试通过，新增规划、地标补查、换行文本、规划后分享、固定域名地图转发、超时和资源失效检查；不使用实际 Token 或消耗调用。前端模块语法检查通过。

## 已知边界

- 已验证明确两站及精确地点映射时，不传 `location` 可以成功；公开文档仍列为当前位置参数，不保证所有请求都可省略。附近查询缺少可信位置时提示，不伪造首站为设备位置。
- 地点澄清、端点不一致或未知结构明确失败，不用示例、直线或残缺路径冒充成功。
- 分享快照默认 7 天有效；百度托管资源有效期未验证，不能承诺同样可用 7 天。
- 痛点与产品价值仍需真实组织者试用。本轮验证技术链路和操作流程。
