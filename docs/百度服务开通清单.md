# 百度地图真实 Demo 接入状态

核验日期：2026-09-26。当前本机已接通 Agent Plan 的真实地点与步行 API，浏览器三站流程、官方地图和固定分享已验收。

## 当前采用的通道

通过百度账号授权，在 Agent Plan 网页领取 Token，再由 CLI 读取现有 SK 并保存到私有 `.env`。当前模式为 `agentplan`。本轮未注册传统开发者、未创建浏览器或服务端 AK，已实际获得地理数据。

CLI 最新只读检查确认 Agent Plan SK 可用、浏览器应用列表为空。CLI 管理授权和凭据；真实地点及路线请求由服务端 HTTP API 执行。无需用户下载 CLI 或把 Token 发到对话中。

| 能力 | 当前实际使用 | 鉴权与状态 |
| --- | --- | --- |
| 真实地点检索 | `GET https://api.map.baidu.com/agent_plan/v1/place` | 服务端 Bearer SK，实测 `status=0`、10 个 POI |
| 真实步行规划 | `GET https://api.map.baidu.com/agent_plan/v1/direction` | 服务端 Bearer SK，实测 `status=0`、道路路径、654 米、727 秒 |
| 官方托管地图展示 | `https://lbs.baidu.com/mapstatic/agentui_resource.html?resource_key=...` | 使用真实 API 返回的 `resource_key`；页面搜索、分段道路和查看入口已验收 |
| 自有页面 JSAPI 底图 | `https://api.map.baidu.com/api?v=4.0` | 需要浏览器 AK，当前未配置；SK 不能替代它 |

托管地图直接呈现百度 API 的真实资源，不需要本项目另行配置浏览器 AK。已在真实浏览器打开并目视核验对应地点、道路、步行线及百度署名；分段路线支持切换。

## 已有真实证据

- `.data/agentplan-place-live.json`：地点结果含地址、坐标、UID，以及顶层 `resource_key`。
- `.data/agentplan-direction-no-location.json`：顶层 `status=0`、`resource_key`；路线位于 `result.navigation_data.walk_routes`，含距离、耗时及 `steps.path`。

Agent Plan 使用 GCJ02 坐标。该次步行请求指定了两个明确地点及 `refer_pois`，省略 `location` 仍成功。公开文档将 `location` 描述为当前位置，单次成功不能作为所有请求可省略该参数的官方保证；不会把所选首站伪装为设备当前位置。

## 本地运行与验收

当前凭据已保存，执行 `npm start` 并打开 [本地 Demo](http://127.0.0.1:4173)。选择 Agent Plan 数据来源，重新搜索真实地点；配置变化后需重启后端。不要覆盖已有 `.env`，不要把凭据提交 Git。

以下浏览器流程已验收，具体证据见 Demo 运行方案：

1. 页面能搜索并加入真实 POI，清楚显示 Agent Plan 来源。
2. 相邻地点的路线、距离和时间能从真实响应解析，顺序变化后结果相应更新。
3. “在百度地图查看”打开与当前结果对应的官方托管地图。
4. 只读分享页保留路线快照及可用的地图查看入口。
5. 上游错误或消歧明确展示，不回退为冒充真实结果的示意数据。

本项目尚未公网部署，本机分享链接仍需可达服务器才能供朋友跨设备访问。

## 可选传统 AK 通道

如后续需要把百度底图直接嵌入自有编辑页，可通过 CLI 获取对应浏览器 AK。传统服务端模式另用服务端 AK，启用地点检索 2.0 与轻量级步行路线，配置后端出口公网 IP 白名单；当前代码没有 SN 签名实现。这两类 AK 是可选的传统模式配置，不是当前 Agent Plan 地点与步行 API 的前置条件。

| 配置 | 用途 |
| --- | --- |
| `CITYWALK_MODE=agentplan` | 当前模式 |
| `BAIDU_MAP_AUTH_TOKEN` | 当前服务端 Agent Plan SK |
| `BAIDU_BROWSER_AK` | 可选自有页面 JSAPI 底图 |
| `CITYWALK_MODE=baidu`、`BAIDU_SERVER_AK` | 可选传统 Place v2 / DirectionLite 模式 |
